## 1. เอาขึ้นออนไลน์

ทำสามขั้นตอนนี้ตามลำดับ ใช้เวลารวมประมาณ 20 นาที

### ขั้นที่ 1 — อัปโหลดไฟล์ขึ้น GitHub

เอาไฟล์ทั้งหมดจากชุดนี้ไปแทนที่ของเดิมใน repo `march007x/sign-speak`
ไฟล์เดิมทั้ง 4 ไฟล์ (`ai-model.js`, `script.js`, `style.css`, `index.html`) ถูกแทนที่ทั้งหมด
ถ้าอยากเก็บของเดิมไว้ดู ให้สร้าง branch ใหม่ก่อนแล้วค่อยอัปโหลดทับ

### ขั้นที่ 2 — สร้างฐานข้อมูล Supabase

1. ไปที่ [supabase.com](https://supabase.com) สมัครและสร้างโปรเจกต์ใหม่ (แผนฟรีพอ)
2. ตั้งรหัสผ่านฐานข้อมูลแล้วเก็บไว้ให้ดี
3. เปิดเมนู **SQL Editor** ทางซ้าย
4. เปิดไฟล์ `supabase/schema.sql` ในชุดนี้ คัดลอกทั้งไฟล์ไปวาง แล้วกด **Run**
5. ไปที่ **Settings → API** จดค่าสองอย่างไว้

| ค่า | ใช้ทำอะไร |
|---|---|
| **Project URL** | ที่อยู่ของฐานข้อมูล |
| **service_role key** | กุญแจสำหรับเขียนข้อมูล **ห้ามเอาไปใส่ในโค้ดที่ push ขึ้น GitHub เด็ดขาด** |

> ถ้า `service_role key` หลุดออกไป ใครก็อ่านและลบข้อมูลทั้งหมดของคุณได้
> มันต้องอยู่ในหน้าตั้งค่าของ Vercel เท่านั้น

### ขั้นที่ 3 — Deploy บน Vercel

1. ไปที่ [vercel.com](https://vercel.com) เลือก **Continue with GitHub**
2. กด **Add New → Project** แล้วเลือก repo `sign-speak`
3. ช่อง Framework Preset เลือก **Other** และ **ไม่ต้องใส่** Build Command
4. กางส่วน **Environment Variables** แล้วใส่สามตัวนี้

```
SUPABASE_URL                = https://xxxxxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY   = eyJhbGciOi... (ค่าจาก Supabase)
IP_HASH_SALT                = ข้อความสุ่มยาวๆ ที่คุณตั้งเอง
```

สำหรับ `IP_HASH_SALT` ให้พิมพ์ตัวอักษรและตัวเลขมั่วๆ ยาวสัก 40 ตัว
หรือถ้าใช้ Mac/Linux เป็น ให้รัน `openssl rand -hex 32` แล้วเอาผลลัพธ์มาใส่
**ตั้งครั้งเดียวแล้วห้ามเปลี่ยน** เพราะถ้าเปลี่ยนระบบจำกัดอัตราการส่งจะรีเซ็ต

5. กด **Deploy** รอประมาณหนึ่งนาที

เสร็จแล้ว ทุกครั้งที่คุณแก้ไฟล์ในหน้าเว็บ GitHub และกด Commit
Vercel จะเห็นเองและอัปเดตเว็บให้ภายในไม่ถึงนาที ไม่ต้องไปกดอะไรอีก

### ตรวจว่าใช้งานได้จริง

- เปิดเว็บ ทดลองกรอกแบบสอบถามแล้วกดส่ง
- กลับไปที่ Supabase → **Table Editor → responses** ต้องเห็นแถวใหม่โผล่ขึ้นมา
- ถ้าไม่โผล่ ให้ดู Vercel → **Deployments → Functions → Logs** จะมีข้อความบอกสาเหตุ

## 3. ปรับความไวของการตรวจจับ

แก้ที่ **`js/config.js`** ที่เดียว ไม่ต้องแตะไฟล์อื่น

### ผู้ใช้บ่นว่า "ทำถูกแล้วแต่ไม่ผ่าน"

ระบบเข้มเกินไป ลองไล่ตามลำดับนี้ ทีละอย่าง แล้วทดสอบ

| แก้ค่า | จากเดิม | ลองเป็น |
|---|---|---|
| `detection.minScore` | 0.78 | 0.72 |
| `detection.maxJitter` | 0.16 | 0.22 |
| `detection.holdFrames` | 18 | 12 |
| `detection.winMargin` | 0.08 | 0.05 |

### ผู้ใช้บ่นว่า "ทำผิดแล้วยังผ่าน"

ระบบหลวมเกินไป ปรับกลับทางตรงข้าม

| แก้ค่า | จากเดิม | ลองเป็น |
|---|---|---|
| `detection.minScore` | 0.78 | 0.85 |
| `detection.winMargin` | 0.08 | 0.14 |
| `detection.holdFrames` | 18 | 24 |

### วิธีดูว่าติดตรงไหนจริงๆ

ในหน้าฝึกมีปุ่ม **"แสดงค่าตรวจสอบ"** อยู่ในการ์ดล่างสุดของแถบข้าง
กดแล้วจะเห็นค่าที่ระบบเห็นแบบสดๆ ทั้งความตรงของแต่ละนิ้ว ตำแหน่งนิ้วโป้ง
และคะแนนของแต่ละเงื่อนไข **เงื่อนไขที่ขึ้นสีแดงคือตัวที่ทำให้ไม่ผ่าน**
ใช้ตรงนี้หาสาเหตุก่อนจะไปแก้ค่า จะตรงจุดกว่าการเดา

### เก็บข้อมูลจริงมาช่วยตัดสินใจ

เมื่อมีคนใช้ระบบสักพัก ให้เข้า Supabase → SQL Editor แล้วรัน

```sql
select * from v_hard_signs;
```

จะเห็นว่าท่าไหนที่คนทำแล้วไม่ผ่านบ่อยที่สุด เรียงจากยากไปง่าย
ท่าที่อยู่บนสุดคือท่าที่เกณฑ์น่าจะเข้มเกินไป

## 4. แก้ปัญหาที่พบบ่อย

### กล้องไม่ขึ้นเลย หน้าจอดำ

- ต้องเปิดผ่าน `https://` เท่านั้น เบราว์เซอร์ไม่ให้ใช้กล้องบน `http://`
  (เปิดจากไฟล์ในเครื่องโดยดับเบิลคลิกก็ไม่ได้ ต้องผ่านเซิร์ฟเวอร์)
- กดที่ไอคอนรูปกุญแจข้างแถบที่อยู่ แล้วอนุญาตให้ใช้กล้อง
- ถ้าเปิดหลายแท็บ ปิดแท็บอื่นที่ใช้กล้องอยู่ก่อน

### กล้องขึ้นแต่ไม่มีเส้นโครงมือ

น่าจะเป็นเพราะ Content Security Policy บล็อกไลบรารี MediaPipe
เปิด Console ของเบราว์เซอร์ (กด F12) ดูว่ามีข้อความสีแดงเรื่อง CSP ไหม
ถ้ามี ให้แก้ใน `vercel.json` โดยเพิ่ม `'unsafe-eval'` ต่อท้าย `script-src`

```
"script-src 'self' https://cdn.jsdelivr.net 'wasm-unsafe-eval' 'unsafe-eval' blob:;"
```

### ซ้าย-ขวาสลับกัน

เปิด `js/config.js` เปลี่ยน `mediapipe.mirrorInput` จาก `true` เป็น `false`

### ข้อมูลไม่เข้า Supabase

ไล่ตามนี้

1. Vercel → Deployments → Functions → Logs มีข้อความอะไรบ้าง
2. ถ้าเห็น `ยังไม่ได้ตั้งค่า environment variables ให้ครบ` แปลว่าลืมใส่ตัวแปร
   หรือใส่แล้วแต่ยังไม่ได้ Redeploy — ต้อง Redeploy หนึ่งครั้งหลังเพิ่มตัวแปร
3. ถ้าเห็น `บันทึกฐานข้อมูลไม่สำเร็จ 401` แปลว่า key ผิด
4. ถ้าเห็น `404` แปลว่ายังไม่ได้รัน `schema.sql` ใน Supabase

### ระบบช้า กระตุก

เปิด `js/config.js` เปลี่ยน `mediapipe.modelComplexity` จาก `1` เป็น `0`
จะเร็วขึ้นมากบนเครื่องเก่าและมือถือ แลกกับความแม่นที่ลดลงเล็กน้อย

## 5. เพิ่มท่าภาษามือไทย

**คลัง ThSL จงใจว่างไว้** เพราะยังไม่มีชุดข้อมูลภาษามือไทยแบบเปิดที่แปลงเป็น
กฎตรวจจับได้โดยตรง แหล่งอ้างอิงทางการคือพจนานุกรมภาษามือไทย ฉบับราชบัณฑิตยสภา
ซึ่งเป็นสื่อวิดีโอและภาพ ต้องมีคนดูแล้วอธิบายท่าออกมาเป็นตัวเลข

การเดาท่าแล้วให้คนฝึกตาม คือการสอนท่าผิดให้คนที่ต้องใช้สื่อสารจริง
ซึ่งแย่กว่าการไม่มีท่าให้ฝึกเลย ระบบจึงบังคับให้ทุกท่าต้องมีแหล่งอ้างอิงกำกับ

### ขั้นตอน

1. เปิดวิดีโออ้างอิงจากพจนานุกรมภาษามือไทย ฉบับราชบัณฑิตยสภา
   หรือสื่อของสมาคมคนหูหนวกแห่งประเทศไทย หรือโรงเรียนโสตศึกษา
2. เปิดไฟล์ `js/vocab-thsl.js` คัดลอกเทมเพลตที่ตรงกับลักษณะท่า
   (มือเดียวนิ่ง / มือเดียวมีการเคลื่อนไหว / สองมือ)
3. เขียนเงื่อนไขโดยใช้ตัวช่วยจาก `js/vocab-asl.js` ได้เลย เช่น
   `allExtended`, `allFolded`, `tipsTouch`, `pointing`
4. ใส่ `source` ว่าอ้างอิงจากไหน และ `verifiedBy` ว่าใครเป็นคนตรวจ
5. เปลี่ยน `status` จาก `"template"` เป็น `"verified"`

ท่าที่ `status` ไม่ใช่ `"verified"` จะไม่ถูกนำมาแสดงในหน้าฝึก

### แนะนำอย่างยิ่ง

ให้ผู้ใช้ภาษามือไทยจริง หรือล่ามภาษามือ เป็นคนตรวจท่าก่อนเปิดใช้
และควรถ่ายวิดีโอท่าจริงมาแสดงแทนแผนผังที่ระบบวาดให้ เพราะแผนผังบอกได้แค่ว่า
นิ้วไหนเหยียดนิ้วไหนพับ บอกรายละเอียดอย่างมุมข้อมือหรือตำแหน่งเทียบร่างกายไม่ได้

## 6. แก้อะไรไปบ้างจากเวอร์ชันเดิม

ปัญหา "แค่มือเข้ามาในกล้องก็ขึ้นว่าถูก" เกิดจากหลายสาเหตุพร้อมกัน

| # | ปัญหาเดิม | วิธีแก้ |
|---|---|---|
| 1 | วัดระยะเป็นสัดส่วนของทั้งเฟรม เช่น `< 0.07` พอยืนไกล มือเล็กลง ทุกจุดอยู่ใกล้กันหมด เงื่อนไข "โป้งจิ้มชี้" จึงเป็นจริงตลอด | หารทุกระยะด้วยขนาดมือ และชดเชยอัตราส่วนภาพ 4:3 |
| 2 | `isDown = !isUp` ไม่มีสถานะ "ไม่แน่ใจ" ค่าต่างกัน 0.0001 ก็ตัดสิน | สามสถานะ มีช่วงกลางที่ระบบจะไม่ตัดสิน |
| 3 | เฟรมเดียวที่ผ่านเงื่อนไขก็ trigger ทันที | ต้องผ่านต่อเนื่อง 18 เฟรม และมือต้องนิ่ง |
| 4 | เทียบแกน y ในพิกัดภาพ เอียงมือแล้วอ่านผิด | หมุน landmark เข้าระบบพิกัดฝ่ามือก่อนวัด |
| 5 | ไม่เคยใช้ `multiHandedness` และไม่ดูทิศฝ่ามือ | พลิกมือซ้ายเป็นมือขวา ใช้กฎชุดเดียว และคำนวณทิศฝ่ามือจริง |
| 6 | วิดีโอถูกพลิกด้วย CSS แต่ landmark ไม่ได้พลิกตาม ทำให้ซ้าย-ขวาสลับ | พลิกพิกัดให้ตรงกับที่ผู้ใช้เห็น |
| 7 | เงื่อนไขทับซ้อนกัน ท่า "ห้า" ผ่านเป็น "สวัสดี" ได้ | ให้คะแนนทุกท่าแล้วเทียบกัน ท่าเป้าหมายต้องชนะอันดับสองด้วยระยะห่างที่กำหนด |
| 8 | เปลี่ยนคำถัดไปทันทีขณะมือยังค้างท่าเดิม ทำให้ผ่านรัวๆ | ล็อก 1.6 วินาทีหลังผ่านแต่ละท่า |
| 9 | ไม่กรองเฟรมที่เชื่อถือไม่ได้ | ปฏิเสธเมื่อมือไกล/ใกล้/หลุดขอบ/ความมั่นใจต่ำ |
| 10 | ส่งข้อมูลด้วย `mode: "no-cors"` อ่านผลลัพธ์ไม่ได้ ข้อมูลหายเงียบ | ส่งเข้า API ของตัวเอง อ่านผลได้จริง แจ้งผู้ใช้เมื่อผิดพลาด |
| 11 | URL ของ Apps Script อยู่ในโค้ดฝั่งผู้ใช้ ใครก็ยิงข้อมูลขยะได้ | กุญแจอยู่ฝั่งเซิร์ฟเวอร์ มีการจำกัดอัตรา กับดักบอท และตรวจค่าทุกตัว |

### รันชุดทดสอบ

ถ้ามี Node ในเครื่อง

```bash
node test/engine.test.js
```

ทดสอบ 58 ข้อ ครอบคลุมทั้งความคงที่ของค่าเมื่อเปลี่ยนระยะและมุม
การบังคับให้ค้างท่า ด่านคุณภาพ และความถูกต้องของคลังท่า

## 7. ข้อจำกัดที่ต้องรู้

**ค่าเกณฑ์ยังไม่ได้ปรับจูนกับกล้องจริง** ชุดทดสอบใช้มือจำลองที่สร้างจาก
แบบจำลองทางเรขาคณิต ซึ่งพิสูจน์ได้ว่าสูตรคำนวณถูกต้อง แต่พิสูจน์ไม่ได้ว่า
ค่าเกณฑ์เหมาะกับมือจริงของคนจริงใต้แสงจริง **ต้องทดสอบกับกล้องจริงและปรับ
ตามหัวข้อ 3** โดยเฉพาะท่า A, S, T, M, N ที่แยกกันด้วยตำแหน่งนิ้วโป้งเพียงอย่างเดียว

**ท่า J และ Z ยังต้องปรับเส้นทางต้นแบบ** เส้นทางที่ใส่ไว้เป็นค่าเริ่มต้นที่
ประมาณจากรูปตัวอักษร ต้องลองทำจริงหน้ากล้องแล้วปรับ `motion.path`
ใน `js/vocab-asl.js` และค่า `motion.minPathScore` ใน `js/config.js`

**ตัวอักษรบางคู่เป็นท่าเดียวกันจริงตามหลักภาษา** F กับ 9, V กับ 2, O กับ 0
ใช้มือเหมือนกันทุกประการใน ASL แยกด้วยบริบทเท่านั้น ระบบจึงยอมรับทั้งคู่
ไม่ใช่ข้อบกพร่อง

**ยังไม่ได้ดูสีหน้าและตำแหน่งเทียบร่างกาย** ภาษามือจริงใช้สีหน้า ทิศลำตัว
และตำแหน่งของมือเทียบกับใบหน้าหรือลำตัวเป็นส่วนหนึ่งของความหมาย
ระบบนี้ดูเฉพาะรูปมือ จึงฝึกได้แค่ระดับ handshape ไม่ใช่ภาษามือทั้งภาษา

**ท่าสองมือรองรับในระดับโครงสร้างแล้ว แต่ยังไม่มีท่าจริง** `maxNumHands`
ตั้งเป็น 2 และเครื่องยนต์ส่งมือที่สองเข้าไปให้เงื่อนไขใช้ได้แล้ว
เทมเพลตอยู่ใน `js/vocab-thsl.js`

**การจำกัดอัตราการส่งใช้การนับแถวในฐานข้อมูล** ซึ่งมีความหน่วงเล็กน้อย
ถ้าเจอการโจมตีแบบยิงพร้อมกันจำนวนมาก ควรเพิ่ม Vercel Firewall
หรือ Cloudflare Turnstile ทับอีกชั้น
